  "revised_document": "# Changelog\n\nAll notable changes to **Amber** are documented in this file.\n\nThe format follows [Keep a Changelog]\n(https://keepachangelog.com/en/1.1.0/) and adheres to\n[Semantic Versioning]\n(https://semver.org/spec/v2.0.0.html).\n\n## [Unreleased]\n\n### Added\n\n- Validate output paths for `replace`, `directives`, and `analyze -o`\n  to prevent traversal outside the project root.\n- Add a fuzz target for `.amber.toml` parsing (`fuzz/`, PR smoke‑test job).\n- Publish a dependency scorecard in `DEPENDENCIES.md` and a CI gate that\n  rejects PRs that increase the direct‑dependency count.\n- Introduce an optional **migrate** feature with the subcommand:\n\n  ```bash\n  amber migrate <crate> --replace-with <FILE> [--dry-run]\n  ```\n\n  The command validates the crate, copies the module into `src/`, updates\n  `lib.rs`/`main.rs`, rewrites imports, removes the dependency via `toml_edit`,\n  and runs `cargo check`. All changes roll back on failure; `--dry-run`\n  previews the plan. Tests cover this flow.\n\n### Changed\n\n- Raise the minimum supported Rust version from 1.80 to 1.85 (enforced by\n  the `msrv` CI job).\n- Update `rustsec` to 0.31, fixing advisory‑database load failures on CVSS\n  4.0 advisories.\n\n## [0.3.0] - 2026-07-11\n\n### Added\n\n- Publish an operator runbook that describes CI integration, exit codes,\n  SARIF consumption, RustSec DB caching, false‑positive handling, and rollback\n  procedures.\n- Add a cross‑platform release job that builds Linux, macOS, and Windows\n  binaries, computes SHA‑256 checksums, optionally GPG‑signs them, and attaches\n  the artifacts to GitHub releases.\n- Replace external crates `colored`, `walkdir`, and `tempfile` with internal\n  std‑only modules located in:\n  - `src/reporting/style.rs`\n  - `src/analysis/walker.rs`\n  - `src/temp.rs`\n- Document technical directives for the three removed dependencies under\n  `docs/directives/`.\n- Introduce an optional **library** feature that stores generated replacement\n  modules in a Padagonia graph database. The feature adds:\n  - `library` CLI subcommand (`list`, `import`, `export`, `path`)\n  - `--library` / `--no-library` flags\n  - `[library]` configuration section\n  - Automatic reuse of stored modules during `replace` and\n    `analyze --propose`.\n- Add a Criterion benchmark suite `amber_library` that measures library\n  lookup, insert, list, save/load round‑trip, and generator integration with\n  and without the library. Record results in\n  `docs/benchmarks/library.md`.\n- Provide replacement templates for `tracing`, `tracing‑subscriber`, `toml`,\n  and `ureq` in `src/replacement/template_data/` with validation tests.\n- Add `library search` and `library remove` subcommands for querying and\n  pruning the Padagonia replacement library.\n- Publish a self‑hosting roadmap for v0.3 in\n  `docs/roadmap/V0_3_SELF_HOSTING.md`.\n\n### Changed\n\n- Refactor the CLI from a single 1,200‑line `src/main.rs` into a\n  `src/cli/` hierarchy (`analyze`, `list`, `score`, `replace`, `directives`,\n  `roadmap`, `library`). `src/main.rs` now only calls `amber::cli::run_cli`.\n- Populate `CargoUsage.used_in_public_api` by tracking usages inside public\n  items and `impl` blocks for external traits/types.\n- Estimate API coverage using `Dependency.public_api_count` when available;\n  otherwise fall back to a LOC‑based heuristic.\n- Resolve transitive dependencies with the full `cargo_metadata` resolve\n  graph, supporting renamed dependencies and walking the complete closure.\n- Remove direct dependencies on `colored`, `walkdir`, and `tempfile` from\n  `Cargo.toml`; the functionality now resides in internal std‑only modules.\n\n### Fixed\n\n- Strengthen SARIF test assertions to verify rule metadata such as\n  `fullDescription`, `defaultConfiguration`, and `help`.\n- Improve usage analysis to detect hyphenated crates (e.g., `comfy-table`\n  imported as `comfy_table`) and dependencies used only through fully‑qualified\n  call sites (e.g., `toml::from_str`). These cases previously appeared as\n  unused.\n\n## [0.2.6] - 2026-07-09\n\n### Added\n\n- Provide SARIF output format for static‑analysis integration.\n- Add JSON, PR/Markdown, and emoji report formatters.\n- Implement a replacement proposal generator with automated `cargo check`\n  validation.\n- Allow configurable safety‑classifier weights via `.amber.toml`.\n- Enrich the RustSec advisory database with CVE counts.\n\n### Changed\n\n- Improve `cargo_metadata` integration for workspace and path‑dependency\n  projects.\n- Refine usage analysis to detect type references, method‑call heuristics,\n  derive attributes, and macro invocations.\n\n## [0.2.0] - 2026-06-10\n\n### Added\n\n- Introduce `amber analyze`, `list`, `score`, and `replace` subcommands.\n- Implement dependency‑usage analysis based on `syn` AST traversal.\n- Add a safety classifier with `SafeToReplace` and `SecurityCritical`\n  categories.\n\n### Changed\n\n- Restructure the project as a library crate with a thin CLI wrapper.\n\n## [0.1.0] - 2026-05-20\n\n### Added\n\n- Release the initial Amber dependency analyzer.\n- Provide basic `Cargo.toml` dependency listing and unused‑dependency\n  detection.\n"
